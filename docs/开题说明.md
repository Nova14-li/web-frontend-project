## 2. 知识点与三个难点
- 这个知识点讲的是什么（一句话）：函数调用自身时，系统用栈为每一层保存参数、局部变量和返回地址；调用时压栈，返回时弹栈。 
- 三个难点：

| 编号 | 难点（一句话） | 学习者卡在哪一步（具体到操作） | 为什么难（抽象不可见 / 步骤太多 / 多步耦合 / 反直觉） |
| --- | --- | --- | --- |
| 难点 1 |每一层递归都有独立的栈帧（参数、局部变量不共享）| 看到 fib(n-1) 里的 n 变了，就以为外层那个 n 也被改了；认为“整个递归过程只有一个 n”，在纸上推演时不停擦掉重写同一个变量| 抽象不可见|
| 难点 2 |return 之后回到调用点的下一行（返回地址与回溯）| 能背“递归会一层层返回”，但说不出返回到哪一行、回到哪个表达式；最常见的错误认识是“返回到函数开头重新执行”，所以画不出回溯路径，也算不出 fib(5) 最后怎么拼出 5| 多步耦合 + 反直觉|
| 难点 3 |调用次数与栈深（递归的时间与空间代价）| 把递归当循环，以为“就是多调用几次”；n 从 20 加到 30 程序突然卡死，但不知道卡在哪，也说不清为什么是指数级| 步骤太多|

## 3. 演示策略（三个难点分别写）
### 难点 1：每一层递归都有独立的栈帧
- 画面构成（有哪些图形元素）：
    - 左侧代码区：固定显示 int fib(int n){ if(n<=1) return n; return fib(n-1)+fib(n-2); }，当前执行行高亮
    - 右侧调用栈区：垂直堆叠的“栈帧卡片”，每张卡显示 fib(n=?)、本层局部状态（如“等 fib(n-1) 的结果”）、返回地址（如“→ 第3行 加号左边”）；卡片按深度换色，越深越冷
    - 底部控件栏：n 输入框、播放 / 暂停 / 单步前进 / 单步回退 / 重置、步骤计数器 第 k / N 步
    - 顶部解说条：一句话说明当前这一步发生了什么，随单步更新
    - 右下角图例：三种颜色分别代表“执行中 / 等待子调用 / 已返回”
- 演示步骤（列出 4 步以上）：
    1. 初始状态：栈里只有 main 一张卡。用户输入 n=3 点“开始”，压入 fib(3) 帧，高亮代码第 2 行，判断 3<=1 不成立
    2. 执行第 3 行，先算加号左边 → 压入 fib(2) 帧。此时 fib(3) 与 fib(2) 同屏并列，两个 n 分别是 3 和 2，用两种颜色标出
    3. 继续压入 fib(1) 帧；fib(1) 命中 n<=1，直接 return 1，卡片变绿并弹出，回到 fib(2)
    4. 压入 fib(0) 帧，返回 0 后弹出；fib(2) 的两个槽填满，算出 1，fib(2) 弹栈
    5. 用户点“单步回退”回到第 2 步：已经弹出的帧会原样恢复，再次看到三层 n 同时存在
    6. 用户把 n 改成 4 重放，观察栈深从 3 变成 4，帧的层数随之增加
- 交互类型（步进推演 / 参数探索 / 对照比较 / 操作判定 / 构建拼装）：步进推演型
- 用户具体怎么操作：播放 / 暂停 / 单步前进 / 单步回退 / 重置；可点击任意一张栈帧卡片，展开该帧的变量快照；可随时改 n 后重新开始
- 可调参数（至少一个，说明它影响什么）：n。它决定最大栈深与帧的总数，改 n 后整条调用序列重新生成；“动画速度”只影响播放节奏，不影响任何结果
- 这个难点如何在交互中被化解：错误认识是“整个递归只有一个 n，被反复改写”。这里每调用一次就真的新增一张独立卡片，两份 n 同屏并列、颜色不同、互不影响；回退时历史帧原样还原。“变量是拷贝”从老师的一句话，变成学生眼前两个同时存在的数字

### 难点 2：return 之后回到调用点的下一行
- 画面构成（有哪些图形元素）：
    - 左侧代码区：高亮当前行
    - 中间表达式待办区：把 fib(3) = [fib(2)] + [fib(1)] 画成两个槽位，已算出的填数字，没算出的显示灰色“等待中”
    - 右侧栈帧卡片：每张卡上单列一行返回地址（如 → 第3行 加号左侧）
    - 底部判定区：弹出 2–3 个选项按钮 + “确认”；判定后出现对/错反馈与一句解释
    - 顶部计分条：连对 x 次 / 本题已错 y 次
    - 一条动画箭头：返回值从弹出帧飞向目标帧的某个槽位
- 演示步骤（列出 4 步以上）：
    1. 单步走到最深的 fib(1) 执行 return 1，画面暂停并提问：“这个 1 要交给谁？返回到哪一行？”
    2. 用户选择。若选“返回到函数开头”→ 该帧抖动、返回地址高亮，提示“回到开头会把 n=1 再算一遍，永远出不来”，并真的播放一段循环重算的反例
    3. 选对 → 播放箭头动画：1 飞回 fib(2) 帧，落进 fib(0)+fib(1) 的左槽，fib(2) 卡片由“等待”变“执行中”
    4. 单步到 fib(0) 返回 0，再次让用户判断这次落哪个槽（右槽）；两槽填满后 fib(2) 算出 1 并弹栈
    5. 这个 1 又需要用户判断：飞回 fib(3) 的哪一侧？——同一机制在更深层再考一次
    6. 全部完成后点“回放回溯路径”，一条折线从最深帧依次穿过每个栈帧回到 main，每段标注“返回到第几行”
- 交互类型（步进推演 / 参数探索 / 对照比较 / 操作判定 / 构建拼装）：操作判定型
- 用户具体怎么操作：每次“即将返回”时从 2–3 个选项中点选一个并确认；选对继续，选错看反例解释后重试；可随时“单步回退”回到上一次判断重做；可关闭提示开关挑战困难模式
- 可调参数（至少一个，说明它影响什么）：n（决定回溯的层数与判定次数）；“提示开关”——开启时栈帧卡片显示返回地址，关闭时隐藏，用户只能靠代码行自己推断，直接改变难度
- 这个难点如何在交互中被化解：能背“一层层返回”，但答不出“返回到哪一行、回到哪个表达式”，潜意识里以为“回到函数开头”。这里把返回地址变成卡片上明写的一行，并且必须由用户自己指认，从错误中理解“返回到哪一行”。

### 难点 3：调用次数与栈深
- 画面构成（有哪些图形元素）：
    - 左上n 滑块（1–32）+ 当前值显示
    - 右上两个大数字：累计调用次数、最大栈深
    - 中部双曲线图：横轴 n、纵轴数量，一条指数增长的总调用次数曲线，一条几乎贴着横轴的线性栈深曲线，当前 n 处有游标与数值标注
    - 下方实测窗口：点“运行”后显示调用计数器飞速跳动 + 进度条
    - 底部换算条：“按每秒 100 万次调用，n=30 需要约 X 秒 / X 年”
- 演示步骤（列出 4 步以上）：
    1. n=5，点“运行”，计数器停在 15 次，最大栈深 5
    2. 把滑块拖到 n=10 → 177 次；拖到 n=20 → 21891 次；拖到 n=30 → 2692537 次，游标在曲线上飞速上抬
    3. 观察栈深曲线：始终等于 n，几乎贴地——时间爆炸，空间只是线性
    4. 打开“实测窗口”在 n=30 下跑 1 秒，进度条只走了一小截，系统据此估算总耗时
    5. 把滑块拖到 n=32 时给出提示“真实机器上这已经是栈溢出 / 超时的量级”
- 交互类型（步进推演 / 参数探索 / 对照比较 / 操作判定 / 构建拼装）：参数探索型
- 用户具体怎么操作：拖动 n 滑块（实时重算并重绘曲线）；开关“现实时间换算”
- 可调参数（至少一个，说明它影响什么）：n（1–32）——同时决定调用次数（指数）与最大栈深（线性），是整个页面的主驱动量；另有“每秒调用次数”只影响换算条显示的现实时间，不影响算法结果
- 这个难点如何在交互中被化解：把递归当循环，没有成本概念，n 一大程序卡死也说不出为什么。这里数字是用户自己拖出来的：从 20 拖到 30，计数从 2 万跳到 269 万；同时栈深只涨到 30。“指数爆炸”和“栈会溢出”从两个形容词，变成一个可数的数和一条看得见的曲线

### 三者差异
- 三个难点分别用什么交互类型：步进推演型、操作判定型、参数探索型
- 遮住标题，别人能否从操作方式分辨出这是三个不同的难点：能
- 三个页面之间可以复用的部分（导航 / 样式 / 播放控件）：
    - 导航：统一的顶部导航条与首页入口，index.html 串起 123 的学习路径
    - 样式：配色变量、字体、卡片与按钮组件、栈帧卡片的基础样式（css/style.css）
    - 播放控件：播放 / 暂停 / 单步前进 / 单步回退 / 重置的 UI 与事件封装（js/common.js），2和3 也复用它做“重放”
